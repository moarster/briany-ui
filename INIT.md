# Фронтенд для панели управления BPM-движком на базе Flowable 8

Документ описывает первую задачу на разработку (инициализацию) проекта

## Общие положения

1. Этот проект развивается одновременно с бэком /home/ivan/Projects/Briany/briany-flowable-engine/
2. Оба проекта используют API-first подход, подключая спецификацию контракта /home/ivan/Projects/Briany/briany-contract как git submodule
3. Изменение/дополнение API в ходе работы - это нормально и приветствуется. Если для той или иной функции требуется доработка бэка, ты это отражаешь в изменениях контракта, а не пытаешься обойти
4. Используй кодогенерацию в той степени которой посчитаешь нужной
5. Это open source проект, поэтому он полностью на английском. Мои инструкции тебе - единственное исключение

## Интерфейс

Меню разделов - сайдбар слева

### Раздел "Applications"

Данный раздел вдохновлен Camunda Web Modeler

1. используем /modeler-apps методы
2. страница списка приложений - это плитка с крупными плашками приложений и псевдоплашкой "new"
   - На плашке написано имя приложения плюс графически stats и статус
3. страница приложения состоит из основной верхней области - файлы приложения, и нижней - описание приложения.
   - файлы трех видов имеют разные иконки: процесс, форма, dmn
   - у каждого файла есть статус
   - при добавлении мы всегда указываем тип файла
   - проваливание в файл = открыть его редактор/конструктор
   - для процесса должна быть возможность перейти в его рантайм (информация о process-definition process-instance)
   - нижняя часть состоит из двух половинок, маленькая узкая слева - редактор имени и описания приложения, основная часть - это README.md которая может быть в режимах чтения (Markdown разметка) и редактирования (текст с подсветкой синтаксиса)
4. нужна возможность деплоить приложение

#### Конструктор bpmn

Задача: используя bpmn-js создать инструмент, создающий минимально совместимый с Flowable BPMN

1. Учти все добавления в XML которые обязательны
2. В каждый узел при настройке надо уметь добавлять поля - <flowable:field name="key">
3. Для Service Task - поле для делегата
4. Нужно реализовать HTTP task
5. Оставляй возможности расширения фукнционала, мы этот конструктор будем делать потом еще долго
6. К стартовым событиям и user task мы должны уметь прикреплять формы (мы ищем все задеплоенные плюс формы из этого приложения)

#### Конструктор bform

Достаточно элементарный form-js

#### Конструктор dmn

Полностью стандартный
